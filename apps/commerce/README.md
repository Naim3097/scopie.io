# Scopie commerce backend (Medusa v2 + Mercur)

The marketplace system of record — products, carts, orders, vendors,
commissions — is **Medusa v2** with **Mercur** (multi-vendor marketplace
engine, MIT). It runs as its own service beside the Scopie API.

## How Scopie consumes it (the integration is live)

The Scopie API's `CommerceService` reads the catalog from three sources in
priority order, so the app works at every stage of the rollout:

1. **Medusa** — when `MEDUSA_URL` is set, `listPicks`/`getById` read the
   store API (`/store/products`), and seller product creation targets the
   Mercur vendor API (that write path is stubbed — see the TODO in
   `commerce.service.ts`, wired when a Medusa instance exists).
2. **Postgres `catalog_products`** — when only `DATABASE_URL` is set, this is
   the authoritative catalog; the Seller Centre (`/sell`) writes here.
3. **Demo array** — zero-infrastructure fallback.

Every catalog write also indexes Meilisearch (`MEILI_HOST`), which becomes the
search source of record for the search bar and the shopper agent.

## Bootstrap Medusa

Not vendored into this repo (Medusa projects are generated by their CLI and
own their migration lifecycle):

```bash
# from apps/commerce
npx create-medusa-app@latest scopie-commerce   # Medusa v2, Postgres required
# then follow Mercur's setup: https://github.com/mercurjs/mercur
```

## Integration contract with the Scopie API

| Concern | Owner | Notes |
|---|---|---|
| Products, variants, stock | Medusa/Mercur (or `catalog_products` pre-Medusa) | `CommerceService` reads via `MEDUSA_URL`; Meilisearch indexes on write |
| Carts | Scopie API | per-identity, bounded in memory (MVP) |
| Orders | **Scopie API** (`orders_ref`) | mirrors Medusa order id + status; the ledger and fulfillment flow live here |
| Vendors & commissions | Mercur (schema mirrored in `sellers`) | vendor panel is the Seller Centre's eventual home |
| Payments & payouts | **Scopie API** | Mercur's default Stripe-Connect payout doesn't serve MY sellers — payments go through the Scopie payment port |
| Escrow & release | **Scopie ledger** | escrow is ledger state; release fires on delivery confirmation / 7-day auto-confirm |

## Fulfillment flow (implemented)

```
paid → seller ships (POST /v1/seller/orders/:id/ship)
     → buyer confirms (POST /v1/orders/:id/confirm-delivery)  ──┐
     → OR 7 days after shipping, the API auto-confirms          ├─► releaseEscrow:
                                                                │   escrow → seller (net) + platform fee
                                                                ┘
```

## Seller Centre

Mercur ships a standalone React vendor dashboard — extend that for the full
Seller Centre later. The MVP Seller Centre (`apps/web/src/app/sell`) covers
onboarding, product authoring, orders, and payable balance against the Scopie
API. Keep product schema ACP-feed-compatible (title, price, media,
availability) so listings are exposable to external AI agents later.
