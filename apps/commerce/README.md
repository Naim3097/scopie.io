# Scopie commerce backend (Medusa v2 + Mercur)

The marketplace system of record — products, carts, orders, vendors,
commissions — is **Medusa v2** with **Mercur** (multi-vendor marketplace
engine, MIT) on top. It runs as its own service beside the Scopie API.

Not vendored into this repo: Medusa projects are generated by their CLI and
have their own migration lifecycle. Bootstrap it here:

```bash
# from apps/commerce
npx create-medusa-app@latest scopie-commerce   # Medusa v2, Postgres required
# then follow Mercur's setup: https://github.com/mercurjs/mercur
```

## Integration contract with the Scopie API

| Concern | Owner | Notes |
|---|---|---|
| Products, variants, stock | Medusa/Mercur | API reads via `MEDUSA_URL`; Meilisearch indexes from webhook/sync job |
| Carts & orders | Medusa/Mercur | `orders_ref` in the Scopie DB mirrors id + status for the ledger |
| Vendors & commissions | Mercur | Vendor panel = the Seller Centre foundation |
| Payments | **Scopie API** | Mercur's default payout module assumes Stripe Connect (not available for MY sellers) — payments and payouts go through the Scopie payment port instead |
| Escrow | **Scopie ledger** | The gateway has no holds; escrow is ledger state (`escrow:<order>`) |

## Seller Centre

Mercur ships a standalone React vendor dashboard — extend that (products,
orders, analytics, Live Studio entry point) instead of building seller tooling
from scratch. Keep product schema ACP-feed-compatible (title, price, media,
availability) so listings are exposable to external AI agents later.
